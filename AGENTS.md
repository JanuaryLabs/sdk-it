### Cross-package invariants

- **Hosts follow the package.** `@sdk-it/spec`'s IR is the single source of truth for what an operation means: its inputs, its responses, and each response's body kind. Generators (`typescript`, `dart`, `python`) and runtimes (`rpc`, `command`) read the IR. A host never parses another host's rendered output (emitted code strings), and never re-derives a fact the IR already records. When a host needs a fact the IR lacks, the fact goes into spec, which every host then follows. Never add API to a generator package for one host's sake.

- **64-bit integers are not special.** The generated type follows the wire encoding: `type: integer, format: int64/uint64` → `number` (`z.number().int()`), `type: string, format: int64/uint64` → `string` (`z.string()`). No `bigint`, no runtime revival machinery — a `type: integer` value past 2^53 is a lossy `number`, and the fix is to encode 64-bit IDs as strings (protobuf-JSON style). `z.int64()`/`z.bigint()` in server code still emit `format: int64` in the spec as documentation. See `docs/recipes/int64-bigint.md` before touching int64 handling.

### TypeScript 7

- **Two TypeScript packages.** The root `typescript` package is the TypeScript 6 API. Nx and typescript-eslint load it. The npm alias `@typescript/native` is the TypeScript 7.1 compiler and API. `npx tsc` runs TypeScript 7.1.
- **Shipped code imports only `@typescript/native/*`.** The ESLint `no-restricted-imports` rule rejects imports of `typescript` and `typescript/*`.
- **Dependency kind.** A package that runs the compiler (`generic`, `cli`) has `@typescript/native` as a regular dependency. `core` and `hono` declare it as an optional peer, so a runtime-only install (such as `@sdk-it/hono/runtime`) has no compiler.
- **`@nx/dependency-checks` cannot read npm alias specs.** Each package that uses `@typescript/native` sets `ignoredDependencies: ['@typescript/native']` on that rule.
- **`npx tsc -v` reports 6.x.** This can occur after an incremental install, because two packages ship a `tsc` bin. Run `npm ci`.
- **Declarations.** The inferred `build-types` target (`tsc --build tsconfig.lib.json`) emits the published `.d.ts` files. esbuild emits only JavaScript.
- **Project references.** When a tsconfig has `references`, the TypeScript 7.1 API program reads each referenced package as source, not as its `.d.ts` (`tsc` and TypeScript 6 read the `.d.ts`). So `analyze` follows calls into workspace packages: a call whose value the handler returns adds the callee's returns and throws, and any other call adds only its throws (`returnTokens` in `packages/generic/src/lib/generic.ts`). `analyze` follows a call into each function that the program reads as source, also in `node_modules`: a package that the `@sdk-it/source` condition resolves to source is followed. A package that ships only `.d.ts` files has no function bodies, so `analyze` does not follow it. The redirect needs matching paths, so `openAnalysisProject` opens the tsconfig by its real path, and the program names its files by real path.

### Dependencies

- `.npmrc` sets `legacy-peer-deps=true`. evlog (a test-only dependency) declares optional framework peers such as `express@>=5.3.0` that the workspace cannot meet, because other tools still require express 4. As a result, npm does not install peer dependencies: declare any peer a package needs as a dependency of its own.
- **A fresh resolve under npm 12.0.x fails with `EALLOWREMOTE`.** Without a lockfile, npm 12 opens the tarball of each package that declares `bundleDependencies` (here `@tailwindcss/oxide-wasm32-wasi`) and refuses it, because its new `allow-remote=none` default treats the registry URL as remote (npm/cli#9800). Pass `--allow-remote=all` to that one command until npm/cli#9818 ships. Do not set it in `.npmrc`: that turns off the protection for every install. An install from the committed lockfile is not affected.

### Releasing

- Run `npx nx release --skip-publish` (build, e2e gate, version bump, commit, `release/<version>` tag), then `npx nx release publish`. Nx loads `NPM_ACCESS_TOKEN` from the gitignored `.env`, and `.npmrc` reads it. Never set or override that variable: a session token in its place makes npm refuse the publish with 403.
- All packages form one fixed release group. `--projects` is refused, so to repair a partial publish, re-run `npx nx release publish`, which skips versions already on npm.
- Before pushing or announcing a release, check that every package's tarball (`https://registry.npmjs.org/@sdk-it/<name>/-/<name>-<version>.tgz`) returns 200. The packages pin each other's exact version, so one missing tarball breaks every install.

## Testing

- Focus on **integration tests** that test entire flows, not unit tests for individual functions.
- **Shared test helpers live in `@sdk-it/testing`** (private, never published). `typecheck(project)` type-checks a project the way its consumers compile it: workspace packages resolve to their declarations. `parseErrorFor(field)` is an `assert.rejects` matcher for a generated client's `ParseError`. Never type-check consumer code through `openAnalysisProject`; its `@sdk-it/source` condition reads source instead of declarations.
- **Temporary directories come from `@zukhruf/testing/fs`.** Write `await using dir = await new TemporaryFiles().directory(prefix)`. Its `path` is the real path, and disposal removes the directory. The lint rule `zukhruf/no-raw-temp-directory` refuses `mkdtemp`, `mkdtempSync` and `mkdtempDisposable` in tests.
- **A test app that imports this repo's packages goes in `/.test-workspaces/`.** Use `workspaceDirectory(prefix)` or `analysisWorkspace(prefix, files, compilerOptions?)` from `@sdk-it/testing`. The folder is gitignored. Node, TypeScript and esbuild find zod, hono and `@sdk-it/*` in the root `node_modules` through the parent folders, as in a user's app. Do not link `node_modules` into a directory in `os.tmpdir()`, and do not give esbuild `nodePaths`. Do not create test folders directly in the repository root: Nx reads the project graph from the root, and a folder that a test removes during that read makes Nx fail.
- **Lint.** The root `eslint.config.mjs` is the only config for the packages. It extends `@zukhruf/eslint` `base`, `tests`, `diagnostics`, `env`, `react` and `nx-project-json`, and `manifest/recommended` from `@zukhruf/eslint/nx`, which checks each `package.json`. `@nx/enforce-module-boundaries` takes `moduleBoundaries()`. `packages/apiref/eslint.config.mjs` adds `@zukhruf/eslint/react` before the root config. Fix each finding at its cause: a lint run has no warnings and no disable comments. A call whose promise a test does not await on purpose (`test.todo`, `it.skip`, `test.each`) gets `void`. A CLI declares the environment variables it reads in `src/startup.ts` (`const env = z.object({...})`). Its bin imports the file, so the check runs before the program parses its arguments. Library code takes values as input.
- **Known lint exceptions.** `manifest/dependency-checks` ignores `@typescript/native` (Nx cannot read the npm alias spec) and, for `packages/apiref`, `@zukhruf/testing`, `zod` and `@react-router/dev` (zukhruf rule gaps #3755, #3756). `hono/runtime/validator.ts` keeps one type assertion for `c.var.input` until the `validate()` API changes (#3745).

### Test Import Rules

- **Always use package module specifiers** in test files, not relative source paths:

  ```typescript
  // ✅ CORRECT
  import { tables, Sqlite } from '@deepagents/text2sql/sqlite';

  // ❌ WRONG - causes type mismatches
  import { tables } from './index.ts';
  ```

- **Why**: TypeScript treats private class members (`#field`) as unique per class declaration. Mixing imports from built packages and source files creates two incompatible types.
