### Cross-package invariants

- **Hosts follow the package.** `@sdk-it/spec`'s IR is the single source of truth for what an operation means: its inputs, its responses, and each response's body kind. Generators (`typescript`, `dart`, `python`) and runtimes (`rpc`, `command`) read the IR. A host never parses another host's rendered output (emitted code strings), and never re-derives a fact the IR already records. When a host needs a fact the IR lacks, the fact goes into spec, which every host then follows. Never add API to a generator package for one host's sake.

- **64-bit integers are not special.** The generated type follows the wire encoding: `type: integer, format: int64/uint64` → `number` (`z.number().int()`), `type: string, format: int64/uint64` → `string` (`z.string()`). No `bigint`, no runtime revival machinery — a `type: integer` value past 2^53 is a lossy `number`, and the fix is to encode 64-bit IDs as strings (protobuf-JSON style). `z.int64()`/`z.bigint()` in server code still emit `format: int64` in the spec as documentation. See `docs/recipes/int64-bigint.md` before touching int64 handling.

### TypeScript 7

- **Two TypeScript packages.** The root `typescript` package is the TypeScript 6 API. Nx and typescript-eslint load it. The npm alias `@typescript/native` is the TypeScript 7.1 compiler and API. `npx tsc` runs TypeScript 7.1.
- **Shipped code imports only `@typescript/native/*`.** The ESLint `no-restricted-imports` rule rejects imports of `typescript` and `typescript/*`.
- **Dependency kind.** A package that runs the compiler (`generic`, `cli`) has `@typescript/native` as a regular dependency. `core` and `hono` declare it as an optional peer, so a runtime-only install (such as `@sdk-it/hono/runtime`) has no compiler.
- **`@nx/dependency-checks` cannot read npm alias specs.** Each package that uses `@typescript/native` sets `ignoredDependencies: ['@typescript/native']` on that rule.
- **`npx tsc -v` reports 6.x.** This can occur after an incremental install, because two packages ship a `tsc` bin. Run `npm ci`.
- **Declarations.** The inferred `build-types` target (`tsc --build tsconfig.lib.json`) emits the published `.d.ts` files. esbuild emits only JavaScript.
- **Project references.** When a tsconfig has `references`, the TypeScript 7.1 API program reads each referenced package as source, not as its `.d.ts` (`tsc` and TypeScript 6 read the `.d.ts`). So `analyze` follows calls into workspace packages: a call whose value the handler returns adds the callee's returns and throws, and any other call adds only its throws (`returnTokens` in `packages/generic/src/lib/generic.ts`). `analyze` follows a call into each function that the program reads as source, also in `node_modules`: a package that the `@sdk-it/source` condition resolves to source is followed. A package that ships only `.d.ts` files has no function bodies, so `analyze` does not follow it. The redirect needs matching paths, so `openAnalysisProject` opens the tsconfig by its real path, and the program names its files by real path.

### Dependencies

- `.npmrc` sets `legacy-peer-deps=true` until #4511 is fixed. evlog (a test-only dependency) declares optional framework peers that the tree does not meet: `react-router@>=7.18.4`, `express@>=5.3.0` and `hono@>=4.13.13`. The comment above the key in `.npmrc` names the versions. As a result, npm does not install peer dependencies: declare any peer a package needs as a dependency of its own. `.npmrc` also sets `strict-allow-scripts=true`, so an install fails when a dependency has an install script that `allowScripts` in the root `package.json` does not name. The pre-commit hook checks both keys (`NpmrcPolicy`).
- **A fresh resolve under npm 12.0.x fails with `EALLOWREMOTE`.** Without a lockfile, npm 12 opens the tarball of each package that declares `bundleDependencies` (here `@tailwindcss/oxide-wasm32-wasi`) and refuses it, because its new `allow-remote=none` default treats the registry URL as remote (npm/cli#9800). Pass `--allow-remote=all` to that one command until npm/cli#9818 ships. Do not set it in `.npmrc`: that turns off the protection for every install. An install from the committed lockfile is not affected.

### Releasing

- A push to `main` is a release. When CI (`.github/workflows/ci.yml`) is green for a push to `main`, `.github/workflows/release.yml` releases that commit: `npx nx release version` versions what the conventional commits ask for, then commits, tags `release/<version>` and pushes, and the `nx-release-publish` action of zukhruf publishes to npm with provenance. A push with nothing to release changes nothing. Do not run `nx release` on a workstation, and do not make `release/*` tags by hand.
- CI runs the network e2e suite (`nx run @sdk-it/source:test-network`, `e2e/index.ts`) when a package that the CLI, `@sdk-it/content-mapper` or `@sdk-it/vite` uses changes (the root project's `implicitDependencies`), so the release gates on tested code. For each of 11 public specs it generates an SDK, type-checks it and runs it on Bun and Node, then downloads the spec and imports it as a module (`.openapi`, or `.openapi.yaml` for YAML) through `tsc` with the content mapper, `node --import @sdk-it/content-mapper/register` and a Vite SSR build with `sdkIt.imports()`. `bun e2e/index.ts <name>` runs one spec. The release builds only the packages that `release.projects` selects (`tag:npm:public`).
- All packages form one fixed release group. The publish step publishes again only the packages that its first run did not publish, so one failed publish does not leave a version half-published. Every release run publishes and skips the versions already on npm, so the next green push to `main` publishes what a failed run left out.
- After a release, check that every package's tarball (`https://registry.npmjs.org/@sdk-it/<name>/-/<name>-<version>.tgz`) returns 200. The packages pin each other's exact version, so one missing tarball breaks every install.

## Testing

- Focus on **integration tests** that test entire flows, not unit tests for individual functions.
- **Shared test helpers live in `@sdk-it/testing`** (private, never published). `typecheck(project)` type-checks a project the way its consumers compile it: workspace packages resolve to their declarations. `parseErrorFor(field)` is an `assert.rejects` matcher for a generated client's `ParseError`. `runNode(args, { env, stdin })` runs a script in its own Node process with a stdin pipe that it closes after `stdin`, and returns `{ exitCode, stdout, stderr }`. It kills a process that runs longer than 60 seconds and rejects, so a test that runs a CLI or a script uses it instead of `spawn`. Never type-check consumer code through `openAnalysisProject`; its `@sdk-it/source` condition reads source instead of declarations.
- **apiref's tests run with Vitest** (`nx run apiref:test` runs `vitest run`). Vitest runs the app's own `vite.config.ts`, so a test gets the app's JSX transform, aliases and `import.meta.env`, which `node --test` lacks. The config leaves out `reactRouter()` when `process.env.VITEST` is set: that plugin loads `routes.tsx`, which loads the spec and rewrites `app/_generated`. A test renders a component with `renderToStaticMarkup` inside a static data router (`createStaticHandler`) whose `root` route loader gives what `useRootData` reads, in the `node` environment, with no DOM. The app exports nothing, so its tests import modules by relative path.
- **Temporary directories come from `@zukhruf/fs`.** Write `await using dir = await new TemporaryFiles().directory(prefix)`. Its `path` is the real path, and disposal removes the directory. The lint rule `zukhruf/no-raw-temp-directory` refuses `mkdtemp`, `mkdtempSync` and `mkdtempDisposable` in tests.
- **A test app that imports this repo's packages goes in `/.test-workspaces/`.** Use `workspaceDirectory(prefix)` or `analysisWorkspace(prefix, files, compilerOptions?)` from `@sdk-it/testing`. The folder is gitignored. Node, TypeScript and esbuild find zod, hono and `@sdk-it/*` in the root `node_modules` through the parent folders, as in a user's app. Do not link `node_modules` into a directory in `os.tmpdir()`, and do not give esbuild `nodePaths`. Do not create test folders directly in the repository root: Nx reads the project graph from the root, and a folder that a test removes during that read makes Nx fail.
- **A test loads a generated SDK by importing its TypeScript entry** (`await import(pathToFileURL(join(dir, 'src/index.ts')).href)`). Node strips the types, so the test needs no esbuild bundle. Bundle only to run the SDK in a `node:vm` realm, which cannot load a module graph (the relative `baseUrl` tests and the realm without web globals in `generate.test.ts`).
- **A `node --permission` child also reads the install.** The pre-push hook runs the tests in a snapshot whose `node_modules` entries link to the repository's install, and the module loader reads the real path. So a test that passes `--allow-fs-read=<repo root>` also passes `--allow-fs-read=<install>`, the path of `import.meta.resolve('zod')` up to its last `/node_modules/`. Without it, the test passes locally and fails only in the hook. `render.test.ts` and `one-module.test.ts` in `packages/typescript` do this; a third such test extracts the helper (#3909).
- **Lint.** The root `eslint.config.mjs` is the only config for the packages. It extends `@zukhruf/eslint` `base`, `tests`, `diagnostics`, `env`, `react`, `nx-project-json` and `github-actions` (which `WorkflowChecks` in `.husky/pre-commit.ts` runs on staged workflows), and `manifest/recommended` from `@zukhruf/eslint/nx`, which checks each `package.json`. `@nx/enforce-module-boundaries` takes `moduleBoundaries()`. `packages/apiref/eslint.config.mjs` adds `@zukhruf/eslint/react` before `sharedConfig`, which the root config exports. The root config adds `modern-node/recommended` after `sharedConfig`, so apiref does not get it. An `ignores` entry in the root config does not keep the rules out of apiref, because ESLint reads that glob from the folder of the config that it loaded. The entry's `ignores` keeps out `@sdk-it/runtime` and the `core` and `spec` files in apiref's browser bundle. `nx run @sdk-it/apiref:check-bundle-lint` (in CI) builds apiref, reads the source maps of `dist/client`, and fails for each file in the bundle that gets a `modern-node/`, `e18e/` or `unicorn/` rule from ESLint. To fix a failure, add the file to that list. A build needs `VITE_SPEC`. Fix each finding at its cause: a lint run has no warnings and no disable comments. The root config also refuses `zod/v3` and `zod/v4` subpath imports (sdk-it is zod 4 only) and `z.instanceof(Blob)` (use bare `z.custom<Blob>()`), and `@zukhruf/eslint` `base` (0.8.6+) refuses a relative import without its file extension, because a published `.d.ts` with `./x` fails under nodenext (TS2835). A call whose promise a test does not await on purpose (`test.todo`, `it.skip`, `test.each`) gets `void`. A CLI declares the environment variables it reads in `src/startup.ts` (`const env = z.object({...})`). Its bin imports the file, so the check runs before the program parses its arguments. Library code takes values as input.
- **Known lint exceptions.** `manifest/dependency-checks` ignores `@typescript/native` (Nx cannot read the npm alias spec) and, for `packages/apiref`, `@zukhruf/testing`, `zod` and `@react-router/dev` (zukhruf rule gaps #3755, #3756). `hono/runtime/validator.ts` keeps one type assertion for `c.var.input` until the `validate()` API changes (#3745).

### Test Import Rules

- **Always use package module specifiers** in test files, not relative source paths:

  ```typescript
  // ✅ CORRECT
  import { tables, Sqlite } from '@deepagents/text2sql/sqlite';

  // ❌ WRONG - causes type mismatches
  import { tables } from './index.ts';
  ```

- **Why**: TypeScript treats private class members (`#field`) as unique per class declaration. Mixing imports from built packages and source files creates two incompatible types.
- **Lint enforces it.** In the root `eslint.config.mjs`, `no-restricted-imports` refuses a relative import (`./x`, `../x`) in a `*.test.ts` or `*.test.tsx` file.
